# AI-Powered After-Call Automation Platform

An after-call documentation pipeline built for the Exology Pioneer Program
Week 4 Final Project. It reads a finished call transcript, looks up the
customer, retrieves the relevant handbook rules, drafts a structured
after-call record with Gemini, validates it against a deterministic
business-rule engine written in code (not prompts), and routes it to
**Auto-Save**, **Human Review**, **Escalation**, or **Non-Interaction** —
never saving anything to the customer record without eventual human
approval.

---

## 1. What's in this repo

```
app/
  intake.py                 Loads and validates a call transcript
  customer_lookup.py         Resolves the caller against data/customers.json
  handbook_search.py          Retrieval over data/handbook/*.md (Chroma + Gemini embeddings)
  documentation_engine.py     Gemini-based structured extraction, grounded in
                               the transcript + retrieved handbook chunks only
  business_rules.py           Deterministic decision engine (the "one rule
                               that matters most": grounding + auto-save gate,
                               both in code, not in the prompt)
  review.py                   Routes a decision to the correct review queue
  storage.py                  Persists the final record to outputs/<queue>/
  evaluation.py                Scores generated records against data/answer_key.json
  dashboard.py                 Builds charts + operational summary from outputs/
  main.py                      CLI entry point: runs the pipeline for ONE transcript

scripts/
  run_batch_pipeline.py        Runs the real pipeline for ALL transcripts in
                                data/transcripts/, then rebuilds the
                                evaluation report and dashboard from the
                                real (non-synthetic) results. Use this one
                                for the actual deliverable.

data/
  customers.json                150 customer records
  handbook/*.md                  ~40 numbered handbook clauses
  transcripts/K-001.txt..K-027.txt   The 27 call transcripts
  answer_key.json                Expected outcome for each transcript (for evaluation)

outputs/                        Generated by running the pipeline (see below)
  records/      AUTO_SAVE decisions
  reviews/      HUMAN_REVIEW decisions
  escalations/  ESCALATE decisions
  archive/      NON_INTERACTION decisions
  evaluation/   evaluation_report.json / .md
  dashboard/    dashboard_summary.json / .md, metrics.csv, charts/*.png

tests/                          pytest suite (129 tests) for every module above
```

> **Note on `tests/generate_sample_outputs.py`:** this script fills
> `outputs/` with random, synthetic placeholder data so `dashboard.py` can be
> exercised without calling Gemini. It is a test fixture only — it is **not**
> the deliverable, and it was only meant to unblock local dashboard
> development. The real output that gets graded/presented must come from
> `scripts/run_batch_pipeline.py`, which runs the actual pipeline against the
> actual 27 transcripts.

## 2. Requirements

- Python **3.10+**
- A Google AI Studio / Gemini API key (free tier is enough for 27 calls)
- Internet access (Gemini API calls for both embeddings and generation)

## 3. Setup

```bash
# 1. Clone and enter the repo
git clone https://github.com/Mariam-Nassar/aftercall-platform.git
cd aftercall-platform

# 2. Create and activate a virtual environment
python3 -m venv .venv
source .venv/bin/activate        # Windows: .venv\Scripts\activate

# 3. Install dependencies
pip install -r requirements.txt

# 4. Configure your API key
cp .env.example .env
# then open .env and paste your real key:
#   GOOGLE_API_KEY=your_actual_key_here
```

Get a key at https://aistudio.google.com/app/apikey — the code reads
`GOOGLE_API_KEY` from the environment (via `python-dotenv`), used both for
Gemini generation (`documentation_engine.py`) and for the Gemini embeddings
used in handbook retrieval (`handbook_search.py`).

## 4. Running it

### 4.1 Run one call (quick smoke test)

```bash
python app/main.py data/transcripts/K-001.txt
```

Prints a summary (customer, category, priority, confidence, decision,
triggered rules) without writing anything to `outputs/`.

### 4.2 Run the full pipeline on all 27 transcripts (the real deliverable)

```bash
python scripts/run_batch_pipeline.py
```

This is the command that actually produces the graded output. It will:

1. Clear out whatever is currently in `outputs/records`, `outputs/reviews`,
   `outputs/escalations`, `outputs/archive` (so no synthetic data survives).
2. Run the real pipeline — intake → customer lookup → handbook search →
   Gemini extraction → business rules → routing → save — for every file in
   `data/transcripts/`.
3. Rebuild `outputs/evaluation/evaluation_report.{json,md}` by comparing the
   real generated records against `data/answer_key.json`.
4. Rebuild `outputs/dashboard/` (charts + summary) from the same real data.

Expect it to take a few minutes (27 sequential Gemini calls). If a
particular call fails (e.g. a transient API error), the script logs which
call and why, keeps going, and exits with a non-zero status at the end if
anything failed — rerun it, or rerun just that transcript with `app/main.py`
and re-save it manually.

### 4.3 Run evaluation or the dashboard on their own

```bash
python -m app.evaluation      # scores outputs/records/ only against the answer key
python -m app.dashboard outputs   # rebuilds charts + summary from whatever is in outputs/
```

`app.evaluation`'s default only reads `outputs/records/`; use
`scripts/run_batch_pipeline.py` if you want all four decision folders scored
together, which is what the grading rubric expects (every call gets a
decision, not just the auto-saved ones).

### 4.4 Run the tests

```bash
pytest tests/ -v
```

129 tests, all passing, covering intake, customer lookup, handbook search,
documentation generation, business rules, review routing, storage,
evaluation, and the pipeline orchestrator.

## 5. How a call is decided (the part that matters most)

Two guarantees live in code, not in prompt wording, per `app/business_rules.py`:

1. **Nothing is invented.** Every field the model can't ground in the
   transcript or handbook is stored as `"Not Stated"`; a record with any
   unsupported or missing required field is routed to Human Review, never
   Auto-Saved.
2. **The caller's words carry no authority over routing.** Phrases like
   *"just mark it resolved"* or *"don't escalate this"* are detected and
   logged for audit but never change the decision — sensitive content and
   handbook-mandated escalation triggers always win, regardless of
   confidence or completeness.

A record only reaches **Auto-Save** when it is complete, grounded,
unambiguous, above the confidence threshold, and free of any escalation or
sensitive-content trigger. Everything else goes to a human — Review or
Escalation — before it can ever be treated as final.

## 6. Known issues / next steps

- `google-generativeai` is deprecated upstream in favor of `google-genai`;
  it still works today but prints a `FutureWarning`. Migrating is a
  reasonable follow-up but out of scope for this pass.
- `data/vector_db/` (the persisted Chroma store) is created on first run and
  is intentionally not committed — delete it if you change the handbook and
  want retrieval to re-index from scratch.
